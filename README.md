# GTNH ME Logistics Enhancement

**专为 GregTech New Horizons（GTNH）设计的 64 槽 AE2 存储与跨网络转运设备。**

A 64-slot AE2 storage drive with scheduled cross-network transfers, multiple destinations, and native storage cell support for GregTech New Horizons.

## 项目简介

GTNH ME Logistics Enhancement 是一个面向 GregTech New Horizons 的 AE2 扩展 Mod，主要用于解决多个独立 ME 网络之间的批量物资转运问题。

核心设备为**存储转运驱动器（ME Transfer Drive）**，在保留原生 ME 驱动器存储功能的基础上，将存储槽扩展至 64 个，并支持按照设定周期，将设备内存储元件中的物品、流体及源质自动转运至其他 ME 网络。

设备支持绑定多个目标 ME 接口、配置转运优先级及存储元件分组，并提供库存访问权限控制、能源保护和跨网络循环检测机制。

## 核心功能

### 1. 64 槽存储驱动器

- 提供 **64 个 AE 存储元件槽位**，分为 8 组，每组 8 槽。
- 兼容 AE2 原生物品、流体存储元件。
- 安装 Thaumic Energistics 时支持兼容的原生源质存储元件。
- 作为源 ME 网络中的普通存储设备运行，可直接向网络提供存储空间。
- 使用原生 AE2 存储 Handler，不维护独立的物品库存副本。

支持三种源网络访问模式：

| 模式 | 功能 |
| --- | --- |
| READ | 源 ME 网络只读 |
| WRITE | 源 ME 网络只写 |
| READ_WRITE | 源 ME 网络可读可写 |

访问模式控制源网络对存储元件的访问，不影响设备内部按规则执行转运。

GUI 可设置整台设备的**存储优先级（Storage Priority）**，默认 0，范围为 -2147483648～2147483647，64 个槽统一使用。该值参与所在源 ME 网络的原生存取排序，遵循 AE2 的黏性、过滤及权限规则；与目标网络的转运优先级分别设置。

### 2. 定时跨网络转运

设备可以按照指定周期，将自身存储元件中的内容自动输出至绑定的目标 ME 网络。

- 默认转运周期为 60 秒。
- 可配置范围为 1～86400 秒。
- 支持物品、流体以及兼容的源质。
- 采用按种类尽可能搬空的转运策略，减少大数量物品的重复操作。
- 不设置额外的中间物品或流体缓存。
- 直接使用目标 ME 网络的原生库存接口，遵循其存储优先级、过滤及容量限制。

**注意：** 转运来源仅限本设备插入的存储元件，不会自动提取源 ME 网络其他驱动器中的库存。

### 3. 多目标网络绑定

使用专用的网络绑定工具，可将一台存储转运驱动器关联至多个目标 ME 网络。

- 最多登记 64 个目标 ME 接口。
- 自动识别多个接口是否属于同一个实际 ME 网络，避免重复处理。
- 支持为绑定目标设置名称和优先级。
- 当目标无法接收全部内容时，可按配置尝试其他目标网络。
- 支持网络连接变化后的重新解析。

每组存储槽支持独立配置：

| 路由模式 | 说明 |
| --- | --- |
| OFF | 关闭该组自动转运 |
| AUTO | 自动使用当前已绑定的目标网络 |
| FIXED | 指定一个或多个绑定目标网络 |

转运时按照目标优先级及稳定的登记顺序进行处理。

每组还可独立设置 **目标填充度（0～100%，默认100%）**。在该组分页的“填充%”输入框设置并应用；0%暂停该组，100%保持原有转运行为。

填充度按**每种物品、流体或源质**分别计算，以目标网络可见的同种存量与模拟可接收余量为基准，不代表整个网络的总字节使用率。实际注入前再次检查，剩余内容可继续尝试其他目标。巨型目标可能因安全探测上限而提前停止；不可见库存、无限及虚空接收端无法提供严格的物理容量百分比。

驱动器支持GT原生扳手采集识别，速度和模式由工具决定。沿用原有元件返还与恢复设备封装路径；实际工具交互和掉落仍需游戏内验收。

### 4. 转运安全与能源保护

为降低跨网络存储操作产生的数据异常风险，设备提供以下保护机制：

- 检测可识别的循环转运路径，阻止直接或间接的网络回流。
- 验证源存储元件、目标网络及网络归属状态。
- 检查真实提取、接收和回填数量。
- 对无法确认的事务保留证据并停止自动重试，避免盲目重复发货。
- 按实际确认接收量结算能源费用，并退还符合条件的未使用预付款。
- 为有限能源网络保留一定储能，降低大批量转运导致断电的风险。
- 采用有界 Tick 调度，将转运工作分散到多个服务器 Tick。

上述机制主要针对正常 API 行为及可识别的异常情况，不保证跨网络硬崩溃时的完全原子性。

### 5. 分配输出总线 / 输出仓（ME，实验性）

**Distributed ME Output Bus** 用作标准 GT 多方块的物品输出总线，将独立分区缓存中的产物排入当前连接的 ME 网络。

**Distributed ME Output Hatch** 提供对应的流体输出仓，继承普通 GT 输出仓，使用同一分区事务与只读 GUI 架构；不使用原生单罐灌装或邻接外排。

- 默认 4 个正常分区，可设 1～16；无容量卡时标称容量为 1600 物品 / 128000 L 流体，各身份独立判断准入。
- 支持经核实的 AE2 原生有限物品容量卡及其过滤；卡内原有内容保留，不导入缓存，也不向 ME 网络公开。
- 流体仓支持 RC2 中 AE2FluidCraft-Rework 1.5.113-gtnh 的已核实有限原生流体元件，遵循实际类型数量与过滤；数量不额外乘1000。
- 默认每 40 Tick 尝试最多 16 种物品，周期可调；ME 离线、缺频道或拒收时保留未确认输出的库存。
- GUI 提供容量卡槽、只读分区、全部应急身份分页、精确数量及故障诊断。
- 配方预检严格遵守正常限制；标准 GT 受保护实际输出可应急超限，排空后释放身份。未保护和特殊直接输出不享有这项保障。

工作台无序合成：**原生 ME 输出总线 ×1 + AE 均分卡 ×1 → 分配输出总线（ME）×1**。配方保守拒绝带非空 NBT 的材料，不能用于迁移旧设备缓存、容量卡或配置。

流体仓对应无序合成：**原生 ME 输出仓 ×1 + AE 均分卡 ×1 → 分配输出仓（ME）×1**，采用相同的空 NBT 材料限制。

物品总线 / 流体仓的固定候选 MTE ID 分别为 **32550 / 32551**；注册前冲突即失败，不覆盖其他设备，仍需整包确认。鸿蒙之眼等特殊机器不在已验证兼容范围；真实 GTNH 注册、GUI、分层蒸馏、拆机与网络验收尚未完成。

固定 AE2 的流体堆栈构造器可能丢弃流体 NBT。流体仓只允许能够通过原生堆栈无损表示的身份进入 ME；不满足时保留缓存并显示诊断，其他流体继续排出。不将该边界描述为任意带 NBT 流体均兼容。

## 相较原生 ME 驱动器的优势

主要优势包括：

**高密度存储。** 单台设备容纳 64 枚存储元件，减少大型 AE 系统中所需的驱动器方块、网络节点及频道数量。

**自动化子网整合。** 可以将生产子网、资源处理子网及其他独立网络中的存储元件内容定期汇集至主网，无需手动搬运存储元件。

**高效批量转运。** 对同种大量库存采用尽可能一次搬运的策略，避免固定小批次所产生的大量重复事务。实际吞吐仍取决于目标网络、能源和服务器性能。

**灵活的物流管理。** 不同存储槽组可指定不同目标网络，结合优先级实现分类转运和目标切换。

**原生 AE2 兼容。** 使用 AE2 原生存储元件与网络库存接口，保留目标网络的过滤、容量和存储优先级行为。

## 安装方法

1. 从正式发布渠道获取 `gtnhmelogisticsenhancement-<version>.jar`，例如版本 `0.1.0-rc.1` 对应 `gtnhmelogisticsenhancement-0.1.0-rc.1.jar`。
2. 将 JAR 放入 GTNH 实例的 `mods` 文件夹。
3. 启动游戏，确认 Mod 正确加载。
4. 在多人服务器中，确保客户端和服务器安装兼容的 Mod 版本。

请使用正式发布 JAR，不要将 `-dev.jar` 或 `-sources.jar` 作为普通游戏 Mod 安装。

首次安装建议备份存档，并在测试世界中验证设备行为。

此次发布前重命名使用新的 Mod ID、注册前缀和资源命名空间，不兼容旧开发版的游戏存档，也不提供旧标识迁移。

## 从源码构建

在项目根目录执行：

```powershell
.\gradlew.bat --gradle-user-home .gradle-user-home build
```

正式游戏 JAR 位于 `build/libs/gtnhmelogisticsenhancement-<version>.jar`。项目保留既定 Minecraft、Forge、AE2、Gradle 和 Java 工具链版本。开发状态、审计及设计记录作为本地内部资料维护；真实游戏验收尚未完成。

版本号沿用现有 Git 版本生成逻辑；本地开发构建可能包含分支、提交和 `dirty` 后缀，以 `build/libs` 中的实际文件名及 JAR 元数据为准。

## 基本使用方法

1. 将存储转运驱动器连接到源 ME 网络。
2. 插入需要使用的 AE 存储元件。
3. 使用专用绑定工具，**Shift + 右键**选择源存储转运驱动器。
4. 再次 **Shift + 右键**目标网络的 ME 接口，建立绑定。
5. 打开存储转运驱动器 GUI，配置目标优先级、各组转运模式与填充度，以及转运周期。
6. 确保网络供能正常、目标网络在线，并具有足够的接收空间。
7. 设备将在设定周期启动自动转运任务。

可以绑定多个目标 ME 接口，也可以在不同槽位组之间分别配置转运规则。

## 已知限制

- 尚未完成所有 GTNH 真实游戏环境下的集成和性能验证。
- 多设备单一AE网络的情况下，如果AE网络能源不足，可能出现多设备争抢能源的情况（会导致缺少能源的设备无法完成转运）。
- 跨 Grid 存储事务不具备硬崩溃条件下的完整原子提交保证。
- 循环检测仅覆盖可识别的网络配置路径，不保证检测第三方设备隐藏的共享库存关系。
- 目标网络主动虚空存储的行为由原生库存接口决定。
- 设备内存储元件可能未纳入部分 AE2 原生网络容量统计界面，但不影响正常库存注册。
